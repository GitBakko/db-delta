01 — BRAND

Identità visiva

Logo · Wordmark · Naming

Il nome DbDelta esprime il cuore del prodotto: db = database, delta = la differenza misurabile fra due stati. Il monogramma è una Δ (delta maiuscolo greco) stilizzata, con una piccola asta interna che evoca la riga di codice modificata e un punto accent che simboleggia il singolo oggetto cambiato.

02 — BRAND

Voce & tono

DbDelta parla come un buon DBA senior: tecnico, preciso, calmo. Mai paternalistico, mai marketing, mai emoji. Quando descrive un'azione distruttiva, lo fa in modo netto ma non drammatico. La voce è in italiano nella documentazione di prodotto e inglese nei messaggi UI (in linea con la convenzione SQL Server tooling).

Principi

01 · Diretto

Verbo, oggetto, fine.

Niente preamboli. "Compare", "Deploy", "Snapshot". Le label sono imperativi.

02 · Cauto

Conta gli oggetti.

Le conferme citano sempre numeri esatti: "Drop 3 tables, alter 12 columns".

03 · Trasparente

Mostra l'SQL.

Mai eseguire qualcosa che l'utente non possa rivedere. Lo script è sempre visibile.

Do & Don't

✓ Usa

"Deploy will drop 3 tables and alter 12 columns. Review the script before continuing."

"5 objects only in source, 2 modified, 847 identical."

"Snapshot prod-2026-05-20.snap created (12.4 MB)."

✗ Evita

"Oops! Looks like something might be a bit off here 🤔"

"Are you really sure you want to do this? This is a serious operation!!!"

"Great job! Your deployment was a smashing success! 🎉"

Tipografia

Geist + Geist Mono

Una sans con un po' di carattere (Geist) e un monospace caratteristico (Geist Mono) — la stessa famiglia che Vercel usa per la sua console: moderne, leggibili, con numerali tabulari attivati di default. Niente Inter, niente Helvetica.

Conventions

  • Numeric features sempre attivi: font-feature-settings: "tnum" 1, "cv11" 1; sul body. Le cifre stanno in colonna nelle tabelle senza configurazione extra.
  • Text-wrap pretty di default sui titoli; text-wrap balance sugli hero.
  • Tracking negativo sopra i 20px; neutro fra 12-18px; wide tracking (0.06em) per eyebrow/uppercase.
  • Mai sotto i 11px nell'app; mai sotto i 12px nelle docs.

Quando usare cosa

  • 2-4px: gap fra icona e label inline.
  • 6-8px: padding interno di controlli compatti (pill, badge, chip), gap fra elementi di una toolbar.
  • 10-12px: padding di card/panel, gap fra sezioni di un form.
  • 16-24px: padding di superfici larghe, distanza fra panel.
  • 32-64px: separazione fra sezioni di pagina.
  • I controlli hanno altezze fisse definite: --control-h-sm 24, -md 30, -lg 36, -xl 44.

Anatomia di una riga

  • Cell-check (28px) — selettore di deploy. Header in stato mixed per select-all parziale.
  • Status pill — comunica il tipo di diff in forma testuale, con dot colorato.
  • Status strip (3px verticale a sx del name) — ridondanza visiva: scrollando rapidamente, il colore è sufficiente.
  • Name — sempre in monospace: gli identificatori SQL sono codice.
  • Type · Schema · Action — metadata, colore --fg-muted.
  • Δ Lines — colonna a destra, allineata a destra, numerali tabulari. Verde +, rosso −.

30 — RIFERIMENTI

Uso con Claude Code

Questo design system è la source of truth per qualsiasi UI di DbDelta — sia GUI (Avalonia) che web/docs. Quando Claude Code lavora sul progetto, deve:

  1. 1 Leggere assets/tokens.css prima di toccare lo stile.

    Tutti i valori (colore, type, spacing, radius, shadow) hanno un token semantico. Mai hardcodare valori — sempre var(--token).

  2. 2 Usare i componenti esistenti come riferimento.

    Il file components-ui.css definisce i building block (btn, input, badge, ecc.); components-domain.css il vocabolario di dominio (Object Diff Grid, Diff Viewer, ecc.). Riusa, non duplicare.

  3. 3 Rispettare le convenzioni di colore semantico per i diff.

    Modified = cobalt, only-source = violet, only-target = amber, destructive = crimson. Mai inventare nuovi colori — se serve un nuovo stato, parlarne prima.

  4. 4 Test light + dark insieme.

    I componenti devono funzionare in entrambi — i token semantici sono già configurati. Verificare visivamente le tinte dei diff (in dark sono attenuate al 30-40% di opacità).

  5. 5 Mapping Avalonia.

    In Avalonia, esportare i token come StaticResource dentro App.axaml; usare la stessa nomenclatura ({StaticResource Primary}, {StaticResource BgRaised}). Il theme switch via RequestedThemeVariant.

Aggiungere un componente

  1. Aggiungere le regole CSS in components-ui.css (generico) o components-domain.css (specifico di DbDelta).
  2. Usare solo token (var(--*)) — nessun valore raw.
  3. Aggiungere una sezione di esempio in index.html dentro un <div class="ds-sample">.
  4. Linkare nella TOC .ds-toc.
  5. Testare il toggle light/dark.
