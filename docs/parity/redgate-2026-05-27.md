## Ordering (#24) observation

DbDelta now emits in object-level topological order; Redgate uses a global
phase grouping (drop all FKs → drop all PKs → drop types/synonyms → create
types → alter sequences → alter tables → create synonyms → rebuilds → modules →
re-add FKs). The two orders differ in grouping but **both honour every
dependency**: types/sequences precede the tables that use them, the inbound FK
is dropped before the `Order` rebuild and re-added after, and all FKs land
last. DbDelta's order is validated by the clean apply + convergence above — no
ordering regression from the #24 restructure.

Locked cosmetic differences (unchanged from 2026-05-25): DbDelta's shorter
batch envelope vs Redgate's six-`SET` preamble + per-batch `PRINT` /
`IF @@ERROR <> 0 SET NOEXEC ON` shells + trailing `xp_logevent` deployment-log
block; `[X_tmp]` vs `[RG_Recovery_N_X]` rebuild naming; `nvarchar(n)` vs
`[nvarchar] (n)`.
