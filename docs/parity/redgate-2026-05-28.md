## Follow-up — cosmetics aligned to Redgate (post-run)

After this run, three of the locked cosmetic differences were aligned to Redgate
(parity > invariants): **(A)** column type names are now bracket-quoted with
spaced args (`[nvarchar] (200)`, `[decimal] (18, 2)`); **(B)** primary keys are
emitted as a trailing `ALTER TABLE … ADD CONSTRAINT … PRIMARY KEY` instead of
inline in `CREATE TABLE`; **(D)** an explicit `COLLATE` is always emitted on
string columns (reverting the #31 omit-when-default optimisation — the
`targetDefaultCollation` plumbing was removed from `ScriptGenerator.Generate`,
`DeployScriptBuilder`, the Avalonia app, and the CLI). The aligned output was
re-verified against the live target (clean apply + empty re-compare). The
captured DbDelta script below is the pre-alignment run artifact. Still NOT
aligned (deliberate): `CREATE OR ALTER` (idempotent, kept), `[X_tmp]` rebuild
naming, the `IDENTITY(1,1)` comma spacing, and the trailing `xp_logevent` block.

## Cross-kind ordering (#24) — the focus of this run

All five new scenarios are **source-only**, so the deploy script must CREATE
each dependency before its dependent. Both tools honour every edge:

| # | Edge | Required order | DbDelta | Redgate |
|--:|------|----------------|---------|---------|
| 13 | computed column → scalar fn | `fnLineTotal` → `PriceList` | ✓ | ✓ |
| 14 | view → view | `vSalesBase` → `vSalesDerived` | ✓ | ✓ |
| 15 | view → scalar fn | `fnTaxRate` → `vTaxedItems` | ✓ | ✓ |
| 16 | schemabound TVF → table | `Region` → `tvfRegionLookup` | ✓ | ✓ |
| 17 | multi-hop table → fn → view | `Warehouse` → `fnStockValue` → `vStockReport` | ✓ | ✓ |

The computed-column expression is byte-identical on both
(`[LineTotal] AS ([dbo].[fnLineTotal]([Qty],[Price]))`), and both keep the
schemabound function/TVF after their referenced table. DbDelta uses object-level
topological order; Redgate uses global phase grouping (drop FKs → drop PKs →
drop types/synonyms → create types → alter sequences → alter tables → create
synonyms/modules → rebuilds → re-add FKs). The two orders differ in grouping but
both are dependency-correct.

## Envelope observation (v0.17.0)

DbDelta's verbose envelope now closely tracks Redgate's:

- **Shared:** `SET NUMERIC_ROUNDABORT OFF`, the six-flag `SET … ON`,
  `SET XACT_ABORT ON`, `SET TRANSACTION ISOLATION LEVEL SERIALIZABLE`,
  `BEGIN TRANSACTION`, per-phase `PRINT N'…'`, `IF @@ERROR <> 0 SET NOEXEC ON`
  gates, and the `DECLARE @Success … SET NOEXEC OFF … succeeded/failed` verdict.
- **Remaining envelope gap (cosmetic):** Redgate appends an `xp_logevent`
  SQL-Monitor deployment-log block after `COMMIT`; DbDelta omits it. Redgate also
  toggles `SET QUOTED_IDENTIFIER ON/OFF` per module; DbDelta sets it once in the
  preamble.

Locked cosmetic differences (unchanged): `CREATE OR ALTER` (DbDelta) vs
`ALTER`/`CREATE` (Redgate) for modules; explicit `COLLATE` (Redgate) vs
omit-when-default (DbDelta, #31); inline PK in `CREATE TABLE` (DbDelta) vs
separate `ALTER TABLE ADD CONSTRAINT` (Redgate); `[X_tmp]` vs `[RG_Recovery_N_X]`
rebuild naming; `nvarchar(n)` vs `[nvarchar] (n)` quoting/spacing.
